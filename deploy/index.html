Atelier de code

Le code s'ouvre, s'explique et s'exécute ici.

Une réponse contient du code ? Un clic l'ouvre dans l'atelier : coloration, numéros de ligne, fichiers gardés d'une session à l'autre. Le bouton Exécuter fait tourner JavaScript immédiatement ; Python demande un téléchargement unique d'environ 12 Mo (Pyodide), puis tout reste hors ligne.

  • 01
    Ouvrir dans l'atelierChaque bloc de code d'une réponse devient un fichier éditable, avec son langage déjà reconnu et son onglet. Un bouton permanent ouvre aussi l'atelier sur une page blanche.
  • 02
    Exécuter JavaScript et PythonJavaScript tourne dans un worker séparé, sans accès à l'interface ni aux conversations. Python utilise Pyodide, téléchargé une seule fois depuis un CDN (environ 12 Mo) et ensuite mis en cache.
  • 03
    Expliquer, corriger, optimiser, testerQuatre consignes prêtes à partir : le fichier ouvert est envoyé au modèle local avec la bonne demande, la réponse revient dans la conversation.
  • 04
    Le code ne part nulle partNi le code, ni la sortie, ni le fichier ne sont envoyés. Seul le premier lancement de Python télécharge Pyodide ; ensuite, tout se passe sur la machine.

« Un assistant personnel qui vous ressemble ne devrait pas avoir besoin de vous observer. » Principe de conception SIMIA

Empreinte

Moins de serveurs, donc moins d'énergie.

Un assistant en ligne consomme à chaque message : votre phrase part vers un centre de données, y rencontre un modèle, revient. SIMIA inverse le trajet. Le calcul se fait une fois, sur la machine que vous possédez déjà, et rien ne circule ensuite.

0 octet

par message

Une fois le modèle choisi, une conversation n'échange plus rien avec le réseau. Ce n'est pas une promesse de confidentialité : c'est mesurable en coupant le Wi-Fi, et SIMIA continue de répondre.

1,4 Go

une seule fois

Le paquet de bureau complet, modèle d'image compris, sur Windows, Linux et Mac Apple Silicon. Ensuite, plus aucun téléchargement de modèle pour converser. Un service en ligne, lui, déplace vos données à chaque requête, indéfiniment.

1 appareil

au lieu d'un parc

L'inférence réutilise le processeur ou la carte graphique déjà installés chez vous. Aucun GPU dédié à faire tourner, refroidir et renouveler pour votre seul usage.

0 copie

à conserver

Rien n'est stocké côté serveur, donc rien à sauvegarder, à dupliquer ni à refroidir. Le seul stockage, c'est votre disque, et il vous appartient.

Chiffres relevés sur cette version : taille réelle du paquet Windows, et comportement vérifié en coupant le réseau. SIMIA ne publie pas d'estimation carbone faute de mesure indépendante, et n'en inventera pas. La fonction Agent web, elle, consulte Internet quand vous l'utilisez, et seulement à ce moment-là.

Origine

Un projet porté, pas assemblé.

SIMIA est né d'une conviction simple : l'intelligence artificielle n'a pas besoin d'un centre de données pour rendre service, et la vie privée ne devrait pas être une option payante.

Questions fréquentes

Ce qu'il faut savoir avant d'installer.

Que fait exactement l'atelier de code ?

Un bloc de code dans une réponse s'ouvre dans l'atelier d'un clic. L'éditeur le garde comme un fichier, avec son langage, ses onglets et ses numéros de ligne. Le bouton Exécuter fait tourner JavaScript directement ; Python passe par Pyodide, téléchargé une seule fois (environ 12 Mo) puis gardé en cache, et la sortie s'affiche sous l'éditeur. Les boutons Expliquer, Corriger, Optimiser et Tests envoient le fichier ouvert au modèle local avec la consigne correspondante : la réponse revient dans la conversation, à côté. Un bouton permanent, dans le panneau latéral et sur l'écran d'accueil, ouvre l'atelier même sans bloc de code.

Il fonctionne dans la version web comme dans l'application de bureau, sans compte et sans serveur. Le code s'exécute dans un Web Worker : il n'a accès ni à l'interface, ni au stockage où vivent vos conversations. Il peut en revanche lire l'IndexedDB (les fichiers de l'atelier et les images), appeler le réseau et consommer du processeur : n'exécutez pas un script dont vous ne connaissez pas l'origine.

Quelle différence entre la version web et la version desktop ?

La version web exécute le modèle dans votre navigateur via WebGPU : pratique pour essayer, mais limitée aux modèles sous 1,9 Go. La version desktop lance le moteur directement sur le GPU de la machine, sans plafond de navigateur : elle accède aux modèles de code les plus gros et à la génération d'images jusqu'à 1024 px.

La version web peut-elle s'installer comme une application ?

Oui. Sur Chrome et Edge, un bouton Installer SIMIA apparaît dans l'interface : l'application obtient son icône et sa propre fenêtre, sans barre d'adresse. Sur iPhone et iPad, passez par Safari puis Partager → Sur l'écran d'accueil. L'interface est ensuite mise en cache : elle s'ouvre même sans réseau.

Faut-il une carte graphique puissante ?

Pas obligatoirement. Une carte récente accélère énormément les réponses (une RTX 2060 suffit pour la génération d'images), mais SIMIA retombe automatiquement sur le processeur. Prévoyez alors davantage de mémoire et un peu de patience.

Quel est l'impact énergétique de SIMIA ?

SIMIA supprime la part réseau et serveur d'un assistant en ligne : pas de requête à envoyer, pas de centre de données maintenu allumé en permanence pour vous répondre. Il reste le calcul, effectué par la machine que vous possédez déjà, sur une durée proportionnelle au modèle choisi : un modèle 1B répond plus vite, et consomme moins, qu'un modèle 14B.

Nous ne publions volontairement aucun chiffre d'empreinte carbone : sans mesure indépendante, ce serait un argument commercial et non une donnée. Le chiffre vérifiable, lui, est simple : une fois le modèle téléchargé, une conversation n'échange plus rien avec Internet — coupez le Wi-Fi, SIMIA continue de répondre.

Où sont stockés les modèles ?

Chaque modèle est téléchargé une seule fois depuis un CDN puis conservé dans le dossier models/ de l'application. Vous pouvez les supprimer ou les déplacer à tout moment.

La génération d'images est-elle filtrée ?

SIMIA n'applique aucun filtre de contenu : il exécute les modèles ouverts que vous choisissez, sans modération ajoutée. À vous d'en faire un usage responsable et conforme à la loi de votre pays.

Windows affiche un avertissement au premier lancement, est-ce normal ?

Oui, et ce n'est pas un virus. Le filtre SmartScreen de Windows prévient pour tout exécutable qui n'est pas signé par un certificat de signature de code, ce qui est le cas de SIMIA : un certificat coûte plusieurs centaines d'euros par an et sert à identifier une société. Le programme est compilé par GitHub Actions à partir du code source public, et son empreinte SHA-256 est publiée dans chaque note de version pour que vous puissiez vérifier le fichier reçu.

Pour éviter l'avertissement : avant de décompresser l'archive, faites un clic droit sur le .zip → Propriétés → cochez Débloquer → OK. Windows oublie alors que le fichier vient d'Internet, et l'exécutable extrait démarre sans rien demander. En PowerShell, sans passer par les Propriétés : Unblock-File .\simia-windows-x64.zip. Fait après extraction, ce réglage ne sert à rien : la marque est déjà recopiée sur l'exécutable.

S'il apparaît quand même : cliquez sur Informations complémentaires, puis sur Exécuter quand même. Aucun droit administrateur n'est nécessaire, ni pour cette étape ni pour l'installation.

Pourquoi les paquets ne sont-ils pas signés ?

Parce que la signature de code exige un certificat nominatif délivré à une société, avec vérification d'identité et clé privée conservée sur un module matériel. Tant que SIMIA n'en a pas, macOS bloque le binaire au premier lancement (xattr -dr com.apple.quarantine) et Windows affiche SmartScreen. Les deux se contournent en trois clics, et le code reste intégralement lisible sur GitHub.
